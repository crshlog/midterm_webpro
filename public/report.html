1. Executive Summary & Domain Overview

The modern academic ecosystem harbors substantial student talent across disciplines such as software engineering, UI/UX design, technical writing, and peer academic tutoring. Local businesses and student organizations frequently seek flexible, cost-effective talent for project-based sprints. However, conventional enterprise recruitment platforms (e.g., LinkedIn, Indeed) impose significant overhead, lack student-specific validation, and are poorly calibrated for micro-engagements.

Ascend Gigs is a purpose-built Freelance Job Board & Candidate Application Portal engineered using the Laravel 11 MVC PHP framework. It provides a transparent, dual-sided marketplace facilitating student job discovery, direct pitch submissions with PDF CV resume attachments, structured employer applicant review workflows, interactive bookmark watchlists, and comprehensive company profile customization.

2. Database Design [Rubric: 20 Points]

2.1 Conceptual Data Model (CDM)

The Conceptual Data Model represents the business domain entities, their attributes, and their cardinalities without exposing physical implementation constraints or primary/foreign key mechanics.

  • User: Represents authenticated participants, categorizing actors into either Student Freelancers or Employers / Organizations.
  • Employer: Represents the organization or club hiring student freelancers, possessing company branding, bio, official website, and social links. (1:1 with User).
  • Job Posting: Represents gig vacancies published by Employers, specifying work mode (Remote, On-site, Hybrid), budget, application deadline, and deliverables. (1:N from Employer).
  • Job Application: Represents a student candidate's pitch, containing pitch narrative, portfolio hyperlink, PDF CV file, and hiring stage status (Pending, Interviewed, Hired, Rejected). (N:1 with Job Posting, N:1 with User).
  • Bookmark: Represents saved opportunities in a student's personal watchlist. (M:N junction between User and Job Posting).

3. Implementation & MVC Architecture [Rubric: 50 Points]

3.1 Laravel MVC Architectural Breakdown

The system adheres strictly to the Model-View-Controller design pattern:

  • Model Layer (app/Models/*): Encapsulates database tables into rich Eloquent objects (User, Employer, JobPosting, JobApplication, Bookmark). Defines relationships, scopes (scopeFilter, scopeActive), accessors (getLogoUrlAttribute, cvUrl), and business rules.
  • Controller Layer (app/Http/Controllers/*): Handles incoming HTTP requests, invokes business logic, enforces authorization gates (e.g. authorizeOwner()), coordinates model persistence, and returns views or redirects with flash messages.
  • View Layer (resources/views/*): Composed of lightweight, semantic Blade templates utilizing component inheritance via layouts/ascend.blade.php, styled with responsive CSS and glassmorphic aesthetics.

3.2 Authentication Subsystem

  • Registration (POST /register): Dual-role account provisioning. Selecting "Employer" dynamically reveals company name and industry inputs in the UI and automatically instantiates the associated Employer profile record in a transactional flow.
  • Login (POST /login): Authenticates credentials using Auth::attempt() with Bcrypt password verification and session()->regenerate() to block session fixation attacks. Includes quick 1-click demo test credentials.
  • Logout (POST /logout): Terminates sessions cleanly via Auth::logout(), invalidating session storage and regenerating CSRF tokens.

4. Analysis & Evaluation [Rubric: 25 Points]

4.1 Architectural Evaluation of Laravel MVC

The Model-View-Controller pattern enforces strict separation of concerns. In Ascend Gigs, database schemas and relationships reside solely in Eloquent models, business workflow orchestration is restricted to controllers, and presentation is encapsulated in Blade templates. This decoupling delivers three major advantages:

  • Maintainability: Modifying database columns or cascade rules requires touching only migrations and models without refactoring UI templates.
  • Testability: Controllers and models can be unit-tested in isolation via automated HTTP and database test mocks without browser dependency.
  • Parallel Team Development: Backend engineers can construct API endpoints and seeders simultaneously while frontend designers polish Blade layouts.

4.2 Eloquent ORM vs. Raw SQL & Eager Loading Audit

Laravel's Eloquent ORM translates database records into active-record instances. Compared to raw SQL queries, Eloquent enhances developer productivity and enforces compile-time safety. To prevent the notorious $N+1$ query defect, all relationship queries in Ascend Gigs utilize eager loading:

// Inefficient Lazy Loading: 1 initial query + N queries for each employer $jobs = JobPosting::all(); // 1 query foreach ($jobs as $job) { echo $job->employer->company_name; // N queries! Total: 1 + N queries } // Optimized Eager Loading (Implemented in Ascend Gigs): $jobs = JobPosting::with('employer')->where('is_active', true)->paginate(9); // Exactly 2 queries executed regardless of the number of jobs displayed!

4.3 Database Normalization Audit

Our 5-table relational schema adheres strictly to Third Normal Form (3NF):

  • First Normal Form (1NF): Every column contains atomic, scalar values. No repeating groups or nested arrays exist. Every table possesses an unambiguous primary key (id).
  • Second Normal Form (2NF): All non-key attributes are fully functionally dependent on the primary key. In composite junction tables like bookmarks, attributes depend strictly on the whole key pair (user_id, job_id).
  • Third Normal Form (3NF): No transitive functional dependencies exist. For instance, employer metadata (company_name, website, bio) is stored exclusively in employers rather than redundantly duplicated across each job_postings record.

4.4 Security Evaluation

Vulnerability Vector Defense Mechanism in Ascend Gigs Implementation Detail
Cross-Site Request Forgery (CSRF) Synchronizer Token Pattern All state-mutating forms (POST, PUT, PATCH, DELETE) incorporate encrypted @csrf tokens verified by Laravel's VerifyCsrfToken middleware.
SQL Injection (SQLi) PDO Prepared Statements Eloquent ORM executes all queries via parameterized PDO statements, rendering SQL injection vectors impossible even in search filters.
Cross-Site Scripting (XSS) Automatic HTML Escaping Blade templating uses {{ $variable }} which passes all user-submitted text through htmlspecialchars(ENT_QUOTES) before rendering.
Broken Access Control Ownership Authorization Gates JobPostingController@authorizeOwner verifies that the authenticated user matches $job->employer_id before permitting edits, status toggles, or deletions.
Malicious File Upload MIME Type & Size Restrictions StoreJobApplicationRequest strictly validates 'cv_file' => 'nullable|file|mimes:pdf|max:5120', and stores uploads on isolated disks.

4.5 System Limitations & Future Improvements

  • Real-time Notifications: Currently, candidates check statuses by polling the status tracker. Integrating Laravel Reverb / WebSockets will deliver push notifications on status changes.
  • In-app Candidate Chat: Integrating direct messaging between employers and shortlisted candidates would eliminate reliance on external email.
  • Stipend Escrow: Integrating a campus payment gateway (e.g. Midtrans or Stripe) would allow employers to lock stipends into escrow upon hiring.
